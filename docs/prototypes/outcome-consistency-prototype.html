One task, repeated in Foundry

How can real agent attempts become a multi-attempt outcome-consistency measure, and what happens when evidence is missing? Explore the captured run, then try simulated outcomes.

What actually happened

Five independent requests were sent to a Foundry prompt agent in a new Sandbox project in Sweden Central. The task was “What is 17 times 23? Reply with only the integer.” The customer-defined success rule for this demonstration was an exact, trimmed answer of 391. Each captured response was 391.

Agent: outcome-consistency-prototype, observed version 1; model deployment: gpt-41-mini-prototype; no tools; maximum 32 output tokens; no conversation shared between attempts. Version 1 was observed in every response; the endpoint was configured to select the latest version, not pinned. Requests received HTTP 429 rate limits during exploration, so the five successful requests were paced. Those service errors and the earlier smoke request are not represented as task failures or included in the five-attempt result.

This page does not call Foundry. The five rows below are captured real responses; every action labelled simulated is fictional. Foundry invocation supplied the responses, the exact-match rule supplied outcomes, and the calculation below is local. No native Foundry cross-attempt reducer or portal publishing path was verified. Custom Foundry evaluators are preview, not production-ready.

How to read this

For one task, the paper’s v3 measure is (2 × success frequency − 1)². Five successes out of five give 1.00; four out of five give 0.36. Five failures also give 1.00: consistency is not success or a suitability verdict.

This demo requires at least two known outcomes and marks the result unavailable if any attempt lacks an outcome. That is a prototype evidence policy, not a finalized product decision; the literal formula also returns 1 for a single attempt. Small samples and uncontrolled factors limit interpretation. The paper’s published code differs from its v3 formula; this demonstration uses the v3 formula. No acceptance threshold is applied.
